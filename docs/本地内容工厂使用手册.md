# Local Factory 本地内容工厂使用手册

更新时间：2026-07-11

这份文档用于日常操作、交接新人和故障排查。请不要把 `config.json` 发给其他人，其中包含 API 凭据。

## 1. 系统能做什么

Local Factory 是运行在本机的内容生产工具，当前主要包含：

- Reddit 视频生成：将音频、随机视频素材、字幕和可选背景音乐合成为竖屏视频。
- 视频素材切割：把长视频快速切成 60-90 秒左右的素材。
- 素材使用率：按 5 秒区间统计素材覆盖率和重复使用情况。
- 自动任务：批量生成视频，按账号分配，并自动提交到 GeeLark。
- 发布记录：查看提交结果，对失败或状态不明确的单条任务进行人工重试。
- 播客生成器：保留的旧视频模板工具；当前 Reddit 内容生产统一使用自动任务。

## 2. 页面入口

| 功能 | 地址 | 使用场景 |
| --- | --- | --- |
| Reddit 手动测试页（导航已隐藏） | `http://localhost:3010/reddit` | 故障排查、参数测试和少量生成 |
| 视频素材切割 | `http://localhost:3010/asset-cutter` | 长视频切割、文件夹分类 |
| 素材使用率 | `http://localhost:3010/asset-usage` | 查看素材重复率、更新索引 |
| 自动任务 | `http://localhost:3010/tasks` | 无人值守批量生成并发布 |
| 发布记录 | `http://localhost:3010/stats` | 查询提交记录、处理失败任务 |
| 数据分析 | `http://localhost:3010/analytics` | 查看今天、昨天和最近7天的 TikTok 视频表现 |
| 抓取配置 | `http://localhost:3010/analytics-settings` | 配置每日抓取时间、TikTokAPI.store Key（可多把）和 GeeLark 账号组 |
| 播客生成器 | `http://localhost:3010/` | 旧播客模板视频 |

## 3. 启动与关闭

### 正常访问

浏览器打开：

```text
http://localhost:3010/tasks
```

能看到自动任务页面，就表示服务正在运行。

### 页面提示“localhost 拒绝连接”

打开 PowerShell，进入项目目录：

```powershell
cd D:\cursor\localfactory
npm.cmd run start
```

看到下面这行表示启动成功：

```text
Podcast video maker is running: http://localhost:3010
```

使用这种方式启动时，关闭 PowerShell 会同时停止服务。当前电脑正常运行时通常由后台进程启动，不需要额外打开 PowerShell。

### 页面显示旧界面

按 `Ctrl + F5` 强制刷新浏览器缓存。

## 4. 重要目录

当前主要数据位置：

```text
项目代码：D:\cursor\localfactory
运行数据：D:\localfactory-data\work
生成成片：D:\localfactory-data\outputs
素材总库：F:\视频素材
```

建议的素材结构：

```text
F:\视频素材
├─ ASMR Food                 # 一个二级文件夹对应一个账号组/素材组
│  ├─ cooking               # 三级文件夹可按类型继续分类
│  ├─ jelly
│  └─ dessert
├─ Minecraft
│  ├─ parkour
│  └─ survival
└─ 其他账号组
```

音频建议单独按批次存放：

```text
F:\音频素材\2026-07-10-心理学
├─ 第一条标题.mp3
├─ 第二条标题.mp3
└─ 第三条标题.mp3
```

## 5. 推荐的日常工作流

1. 准备当批音频，每个音频文件使用容易识别的名称。
2. 检查对应素材组是否已经更新索引。
3. 先用 Reddit 生成器生成 1-3 条进行画面、字幕和声音测试。
4. 测试正常后，在自动任务页面创建小批量任务。
5. 先跑 10-20 条，检查账号分配和发布时间。
6. 确认无误后，再扩大到 60、150 或更大的批次。
7. 在发布记录页面处理失败或状态不明确的单条任务。
8. 每周查看素材使用率，决定补充素材或更换素材组。

不建议第一次就直接提交 300 条。

## 6. 视频素材切割

进入“视频素材切割”页面。

### 长视频切割

1. 填写素材组名称，例如 `asmr-food-0710`。
2. 选择长视频输入目录。
3. 需要读取下级文件夹时，勾选“读取输入目录下的子文件夹”。
4. 选择切割后保存目录。
5. 设置最短、最长秒数，常用值为 `60` 和 `90`。
6. “每个长视频最多读取秒数”填 `0` 表示读取完整视频。
7. 编码模式优先选择“快速切割（不重新编码）”。
8. 点击“开始切割”，等待进度完成。

快速切割速度最快，但切点会受原视频关键帧影响，实际时长可能与设置值有少量差异。只有需要统一尺寸或格式时才选择重新编码。

### 文件夹分类与分配

- “复制”会保留原文件，适合第一次整理。
- “移动”会改变原文件位置，确认目标目录正确后再使用。
- 勾选“将一级子文件夹作为整体”时，会按文件夹整体复制或移动。

## 7. 素材组和素材索引

素材组是已经建立索引的素材目录，优点是：

- 能记录每段素材的使用次数。
- 能按 5 秒区间计算重复覆盖率。
- 已经高频使用的片段会降低后续抽取优先级。
- 自动任务可以直接选择素材组，不需要再次填写视频目录。

### 素材发生变化后怎么做

- 只是在已有素材组中增加、删除视频：进入“素材使用率”，选择该组，点击“更新当前账号组”。
- 新增完整账号组：先通过素材切割或素材库同步建立该组，然后刷新页面。
- 素材组显示数量与磁盘不一致：点击“更新当前账号组”，等待索引完成后再刷新。

### 素材使用率怎么看

- 覆盖率越低，说明还有较多未抽取片段。
- “低重复库存”越高，越适合继续使用。
- 高复用素材仍有可能被抽中，但优先级会降低。
- 同一源视频重叠使用的 5 秒区间会被计入重复区间。

## 8. Reddit 手动测试页

该页面已从导航隐藏，仅作为故障排查和少量参数测试工具；日常生产统一使用自动任务页面。

### 基本步骤

1. 选择素材组，或者填写临时视频素材目录。
2. 选择音频目录。
3. 背景音乐目录可留空；填写后会随机抽取背景音乐并低音量混入。
4. 设置生成视频总条数；音频会按文件顺序循环使用，直到达到目标数量。
5. 设置素材抽取时长，常用固定值为 `5` 秒。
6. 设置字幕位置、字号和动画模式。
7. 保持“使用 ElevenLabs 识别字幕”勾选。
8. 点击“开始混剪”。

### 字幕缓存

同一个音频第一次识别时会调用 ElevenLabs；再次使用同一音频生成多个视频时会读取缓存，不会每个模板重复识别。

如果字幕识别提示权限不足，需要为 ElevenLabs API Key 开通 `speech_to_text` 权限。

### 素材去重参数

默认参数适合轻量随机变化：

- 缩放：改变画面裁切比例。
- 旋转：正负角度随机微调。
- 镜像概率：例如 `30%` 表示约三成素材片段水平翻转。
- 亮度、对比度、饱和度：在给定范围内随机变化。
- 锐化强度：`0.2` 表示滤镜强度，不是 `1.2`。
- 变速：每段素材在最小值和最大值之间随机变速。
- 蒙层数量填 `0` 表示不使用蒙层。

修改字幕或去重参数后，要点击对应的“保存设置”，否则刷新页面会恢复旧值。

## 9. 自动任务

自动任务适合批量生成并自动发布。

### 9.1 任务与素材

1. 填写任务名称，建议包含日期、内容类型和账号组。
2. 在“素材来源”中选择已有素材组。
3. 临时素材不需要建立索引时，选择“临时本地目录”，再选择目录。
4. 选择音频目录。
5. 背景音乐可留空。

已有素材组优先使用素材组，不要再选择临时目录，否则素材使用率会分散到不同记录中。

### 9.2 生成规则

- 生成视频总条数：直接填写最终需要的数量。例如 15 个音频生成 40 条，会按 `1-15、1-15、1-10` 的顺序循环。
- 每段素材时长：推荐从 `5` 秒开始测试。
- 字幕位置和字号：先小批量测试，避免字幕遮住画面重点。
- 字幕效果：“逐词高亮”更活跃，“整句字幕”生成和阅读更稳定。
- 编码模式：“更快”适合批量，“更清晰”会增加生成时间。
- 自动识别字幕默认开启，并复用字幕缓存。

### 9.3 选择账号

1. 先选择 GeeLark 分组。
2. 可继续输入账号名称筛选。
3. 点击“全选筛选结果”。
4. 检查“已选账号数”是否正确。

常用 TikTok 标签文案可点击“新增当前”保存到文案库。后续从下拉菜单选择；修改后可点“更新”，不再使用时可删除。临时文案无需保存也能直接发布。

视频按选择的账号顺序轮流平均分配。比如 20 条视频、20 个账号，每个账号得到 1 条；20 条视频、10 个账号，每个账号得到 2 条。

执行队列会按具体日期和分钟展示排期。多个发布时间会换行显示，便于提交前核对每一轮账号的发布时间。

### 9.4 发布时间

- 起始发布时间必须至少晚于当前时间 5 分钟。
- “同账号间隔”只作用于同一个账号的第 2、3 条视频。
- 不同账号的第一条视频使用相同起始时间。

示例：5 个账号、10 条视频、起始时间 18:30、间隔 15 分钟：

```text
5 个账号的第一条：18:30
5 个账号的第二条：18:45
```

### 9.5 发布安全上限

默认值：

```text
单批调用上限：300
每日调用上限：300
自动重试：只重试 1 次
重试等待：2 分钟
```

上传失败或 GeeLark 明确返回失败时，系统会跳过当前视频继续处理其他视频，主任务结束后再重试一次。

注意：自动重试也计算 GeeLark 调用次数。如果计划发布 300 条，达到上限后就没有重试额度。建议每日只安排 270-285 条，为重试保留余量。

### 9.6 创建任务前检查

- 素材组是否正确。
- 音频目录是否只包含本批音频。
- 预计视频数是否正确。
- 账号数量是否正确。
- 文案和标签是否正确。
- 起始时间是否正确。
- 同账号间隔是否正确。
- 单批和每日调用上限是否符合计划。

确认后点击“加入任务队列”。

## 10. 队列状态和停止任务

常见状态：

| 状态 | 含义 |
| --- | --- |
| 排队 | 等待前面的任务完成 |
| 生成中 | 正在混剪视频 |
| 发布中 | 正在上传并提交 GeeLark |
| 等待重试 | 明确失败任务将在 2 分钟后重试一次 |
| 待人工处理 | 有失败或状态不明确的视频 |
| 等待确认发布 | 生成完成，但创建时关闭了自动发布 |
| 已完成 | 生成和发布均处理完成 |

点击“停止”会停止尚未完成的本地任务，但已经提交给 GeeLark 的任务不会被撤销。

如果任务处于“等待确认发布”，点击“继续执行”才会进入发布阶段。

## 11. 发布记录与人工重试

进入“发布记录”页面，可以按时间、分组、账号或视频搜索。

“待重新执行”只展示：

- 发布失败。
- GeeLark 返回状态不明确，需要人工核实。

处理步骤：

1. 先在 GeeLark 后台搜索账号、任务名称和计划时间，确认是否已经存在。
2. 如果已经存在，不要重新执行。
3. 确认没有提交成功后，再点击单条“重新执行”。

不要因为页面报错直接重新创建整批任务。系统有本地记录、远端历史和安全账本三层查重，但人工核实仍是处理“不明确状态”最稳妥的方法。

### 11.1 TikTok 数据分析

1. 从左侧进入“数据分析”。
2. 进入“抓取配置”，确认 TikTokAPI.store API Key 已配置。
3. 设置每天执行时间，勾选一个或多个 GeeLark 账号组，再开启“每日自动抓取”并保存。系统执行时会实时读取这些分组的当前账号，每个账号调用一次 `User Posts`，读取最近 10 条公开视频。
4. 数据分析页面不提供手动抓取操作，只展示今天发布、昨天发布和最近7天发布视频的当前累计表现。
5. 页面展示播放、点赞、评论、分享、收藏和综合互动率，并按账号与发布时间尝试匹配本地发布记录。
6. 在“视频表现明细”点击“查看”，可检查该视频每个素材的抽取区间、同源素材复用比例、精确时间段重叠率，并与其他成片播放量对照。

API Key 保存在配置文件或工作目录的 `tiktok-analytics-settings.json` 中，页面和接口仅显示脱敏值。多把 Key 在抓取配置页按每行一把填写，系统会优先选择当天使用次数较少的 Key；遇到单把 Key 的鉴权、限流或额度错误时自动切换下一把。当前每把 Key 按每天 100 次进行本地限制，两把合计最多 200 次。接口失败不会把上一次成功数据覆盖成 0；置顶视频会按真实发布时间重新排序。

## 12. 自动清理与磁盘

当前规则：

- 每条视频生成成功后，立即清理该视频的渲染临时目录。
- 有成功发布记录的最终 MP4，从计划发布时间起保留 48 小时。
- 服务启动时检查一次，之后每 6 小时检查一次。
- 发布失败、状态不明确、等待发布和没有发布记录的视频不会自动删除。
- 磁盘剩余空间低于 20 GB 时，系统拒绝创建新的自动任务。

生成成片目录：

```text
D:\localfactory-data\outputs
```

不要手动删除正在生成、等待发布或待重试的视频。

## 13. 常见问题

### 页面打不开

原因通常是本地服务没有运行。按第 3 节重新启动。

### 页面改动没有出现

按 `Ctrl + F5` 强制刷新。

### 提示素材组没有可用视频

检查源文件是否存在，再到素材使用率页面更新当前账号组索引。

### 素材数量与文件夹不一致

索引没有更新。点击“更新当前账号组”，完成后刷新。

### 字幕识别失败

检查网络、ElevenLabs 额度和 `speech_to_text` 权限。已有字幕缓存不会重复调用 API。

### GeeLark 发布失败

到发布记录页面查看具体错误。单条明确失败会自动重试一次；状态不明确时先去 GeeLark 后台核实。

### 达到每日调用上限

当天不再调用 GeeLark。等待下一天，或者减少每日计划数量。不要为了继续发布随意提高安全上限。

### 视频生成越来越慢

常见原因：音频更长、开启更清晰编码、逐词字幕、磁盘读写繁忙、源素材在机械硬盘、并行运行其他转码软件。

### 停在某个进度很久

先观察任务消息是否仍在变化。生成子进程异常退出时系统会终止该任务，不会继续进入发布阶段。确认失败后再点击继续或重新创建小批任务。

## 14. 备份与迁移

建议备份：

```text
D:\cursor\localfactory   # 程序代码和配置
D:\localfactory-data\work                     # 任务、发布记录、字幕缓存、素材使用率
F:\视频素材                                     # 素材总库
```

`D:\localfactory-data\outputs` 是可自动清理的成片目录，不是长期素材库。

迁移到新电脑后需要：

1. 安装 Node.js 和 FFmpeg。
2. 复制项目代码。
3. 执行 `npm install` 安装依赖。
4. 修改 `config.json` 中的目录路径。
5. 安全配置 ElevenLabs 和 GeeLark 凭据。
6. 启动服务并先跑 1 条测试视频。

## 15. 新人首次操作建议

第一次只做以下测试：

1. 准备 1 个素材组。
2. 准备 1 条 30-60 秒音频。
3. 在 Reddit 生成器生成 1 条视频并检查字幕。
4. 在自动任务中选择 1 个账号，生成并发布 1 条。
5. 到发布记录确认任务 ID 和计划时间。
6. 成功后再增加到 5 条、20 条，最后才进行大批量。

先验证完整链路，再扩大数量，能显著降低错误批量发布和 GeeLark 积分损耗风险。
