# Image content upload and controlled URL fallback

## Goal
Implement actual image content ingestion, regional URL compatibility, real PNG decoding and structured errors without paid generation.

## Decisions
- New app-only psychology_upload_topic_png accepts bounded PNG base64 generated by the widget from a local File. Transport is the authenticated MCP JSON channel rather than a new multipart route; avoids extra upload credentials/CORS. No model-produced bytes, remote downloads or ChatGPT upload helpers on this path.
- selectFiles/fileParams expose IDs/URLs, so retain URL fallback. The requested oaisdmntpr plus 1–14 lowercase alphanumerics Azure pattern accepts region changes but not arbitrary tenants, hyphens, nested domains, userinfo or ports. Prefix is not proof of OpenAI ownership.
- Share leases, permissions, R2 checkpoints and receipts. Byte identities derive from SHA-256, URL identities retain file ID; transport changes under an accepted request conflict. Local reselection after widget remount checks hash. No bytes/signatures in UI state, operation JSON or returned errors.
- Validate CRC/structure and decode compressed scanlines/filters/Adam7/palettes with bounded row buffers and exact output length. Static PNG only, 8 MiB/4096px bounds. Corrected an old fixture's invalid IDAT CRC, previously missed by header-only checks.
- Structured failures include ok/status/errorCode/message and hostname only. UI resource v2 and new private tool require metadata refresh.
