# 官方 API 小说自运营：文案改写策略 v1

## 范围

- 仅作用于官方 TikTok API 小说自运营。
- GeeLark 第三方策略不变。
- 所有样本继续纳入统计，但只有具备本地文案映射且诊断为 `rewrite_test` 的视频才自动改写。

## 执行顺序

1. 固定规则先诊断问题层：小说、钩子、前三秒、3-10 秒铺垫、中段、转场或结尾。
2. 生成绑定的 `rewriteBrief`，只指定一个主要改写变量。
3. AI 必须按 `rewriteBrief` 局部修改，并保留人物关系、关键事件、因果关系和结局事实。
4. 输出完整新文案、改动前后对照、数据证据和改写原因。
5. 原文不覆盖；新文案作为派生版本保存，并调用 ElevenLabs 生成对应新音频。

## 第一版规则

- 前 3 秒流失超过 30 个百分点：只改 0-3 秒开头。
- 3 秒留存显著低于同账号同长度中位数：只改钩子。
- 3-10 秒连续快速下降：删除铺垫和重复解释，把冲突提前。
- 中段出现最大断崖：只修改对应估算句及相邻承接。
- 后 30% 出现最大断崖：强化结尾回报，不改变原结局。
- 平均观看比例低于 35%：保留主线，压缩重复描述，提高事件密度。
- 留存好但播放低：仅调整分发，不改文案。
- 播放和留存均优秀：保留复用，不覆盖原文。

## 版本证据

每个派生音频保存：问题层、改写范围、目标秒段、估算原句、改写目标、唯一变量、保留事实、改动日志、来源音频 ID、来源视频 ID 和计划 ID。
